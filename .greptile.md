# CloudSprocket -- Greptile Reviewer Context

## What this project is
CloudSprocket is a local-first cloud workbench desktop app. It lets developers
inspect, manage, and deploy to cloud providers (AWS, Azure) and local emulators
(LocalStack, floci-az) from a single GUI without leaving their machine.

## Tech stack
- **Frontend**: React 19 + TypeScript, Tauri v2 shell, Tailwind v4 + shadcn/ui
- **Backend sidecar**: Go 1.26, JSON-RPC over stdin/stdout to the Tauri host
- **IaC deploy**: OpenTofu (azurerm provider) via bundled recipes
- **Emulators**: LocalStack (AWS), floci-az (Azure ARM on :4577)
- **DB**: SQLite via the Go daemon
- **Build**: pnpm 10 monorepo, Node 24

## Repository layout
```
apps/desktop/          # Tauri v2 shell + React UI
  src/
    views/             # One file per workspace tab (Lambda, RDS, S3, etc.)
    lib/               # backend.ts (RPC client), azure-inventory.ts, etc.
    types/             # Shared TypeScript types synced with Go models
backend/daemon/
  internal/
    app/               # Core service layer -- all RPC handlers live here
    azureadapter/      # Azure SDK wrappers (flocilocal + flocilive)
    flociaz/           # floci-az ARM emulator manager
    deploy/            # OpenTofu deploy orchestration
    recipes/           # Bundled IaC recipe definitions
    models/            # Shared Go structs
    tofu/              # OpenTofu runner wrapper
legacy/pyside-v1/      # Archived Python app -- reference only, not active
```

## Key architectural patterns
- The Go daemon is a sidecar spawned by Tauri; communication is JSON-RPC.
- All cloud calls go through the `app.Service` struct in `backend/daemon/internal/app/service.go`.
- AWS and Azure are both supported; provider selection is per-workspace-session.
- Local emulator support is first-class: LocalStack for AWS, floci-az for Azure.
- Deploy uses OpenTofu recipes; the runner is in `internal/tofu/runner.go`.
- The UI is being migrated from AWS Cloudscape to Tailwind v4 + shadcn/ui.

## What to focus on during review
- **Type safety** across the RPC boundary (Go structs <-> TypeScript types in `src/types/`)
- **Error handling** in Go sidecar -- panics or unhandled errors crash the sidecar silently
- **Race conditions** in the Go service layer (concurrent workspace refresh calls)
- **Azure emulator vs live path divergence** -- `flocilocal.go` vs `flocilive.go` must stay in sync
- **Deploy safety** -- OpenTofu apply/destroy in `internal/deploy/` should never run without preflight checks
- **Test coverage** -- each `azure_*.go` and `aws_*.go` handler should have a matching `*_test.go`

## What NOT to flag
- The `legacy/pyside-v1/` directory -- archived, not maintained
- `node_modules/`, `.tmp/`, `.tools/` -- generated/vendored
- Cosmetic lint issues (formatting is enforced by CI)
- README staleness -- the README lags intentionally during active rewrites
