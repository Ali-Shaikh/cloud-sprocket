# CloudSprocket v0.6 — Cloud Breadth (implementation plan)

Status: planning. Provider-agnostic, works against **real AWS and local LocalStack alike** (no Pro
token). Theme C of the roadmap. Read-first, then narrow safe actions.

## Why this fits the north star
The existing inventory pattern (S3 + EC2 for AWS, resource groups + VMs for Azure via floci) proves
the model: one AWS SDK client whose endpoint is overridden for LocalStack but otherwise hits real
AWS. v0.6 widens that to the services recipes actually create, so a user can **see and manage what
they deployed** — locally or in real cloud — by switching profile. No emulator lock-in.

## Scope: new read-only inventory panels (AWS)
Add these service panels, mirroring the S3/EC2 view + adapter pattern already in
`backend/daemon/internal/awsadapter` (SDK client, optional `endpoint_url` override) and
`apps/desktop/src/views`:

1. **Lambda** — list functions (name, runtime, memory, last modified), view config + recent
   CloudWatch logs, **Invoke** (test payload) as the one safe write action.
2. **DynamoDB** — list tables, describe (keys, item count, GSIs), scan first N items (read-only).
3. **SQS** — list queues, attributes (depth, in-flight), peek messages without consuming
   (`receive` with visibility 0 / the LocalStack SDK "list without side effects" idea — for real
   AWS use a bounded receive).
4. **SNS** — list topics + subscriptions.
5. **RDS** — list instances (engine, status, endpoint, class).
6. **CloudWatch Logs** — browse log groups, tail recent events (reuse the log-command idea but in-app).
7. **IAM** — list roles/policies (read-only) so users can inspect what recipes created.

## Backend pattern (per service)
- New `internal/awsadapter/<service>.go`: an interface + SDK-backed impl, constructed with the
  resolved profile creds; for local, set `BaseEndpoint = http://localhost:4566` (same override S3/EC2
  use). `sysproc.Hide` not needed (SDK, not exec).
- RPCs in `service.go`: `aws.<service>.list`, `aws.<service>.describe`, plus the one action per
  service (`aws.lambda.invoke`, `aws.sqs.peek`). Reads bounded by a timeout like the Azure inventory
  (`withAzureTimeout` pattern → add `withAWSTimeout`).
- Region from the locked profile/session; allow a region switcher like EC2 already has.
- Tests: `httptest`/SDK stub asserting list/describe mapping; gate live tests behind an env flag.

## Frontend pattern (per service)
- A workspace tab per service (wire into the AWS workspace nav like S3/EC2), card/table list +
  detail pane, reusing existing components (tables, `OutputRow`/Copy, status badges, EmptyState).
- Region selector; refresh; loading + empty + error states. Browser mock entries in `backend.ts`.

## Sequencing (ship one service at a time, each its own commit + exe rebuild)
1. Lambda (highest value — recipes deploy Lambdas; invoke + logs closes a real loop).
2. DynamoDB. 3. SQS. 4. SNS. 5. RDS. 6. CloudWatch Logs. 7. IAM.
Stop wherever the budget runs out; each service is independently shippable.

## Guardrails
- **Read-first**: only the listed safe actions (invoke/peek) write; everything else is read-only.
  Any destructive action (delete queue/table/function) is out of scope for v0.6.
- Works identically on real AWS and LocalStack via the endpoint override — verify each against both.
- Reuse the deploy preflight idea: if the target isn't reachable, show an actionable empty-state.

## Conventions
Branch `feat/v0.6-cloud-breadth` off `dev`; atomic conventional commits, no Claude co-author
trailer; British English; rebuild exe per service; four-check gate (go test / typecheck / vitest /
build:exe); PR into `dev` for review.

## Deferred
AWS replicator (mirror real→local, Theme B/Pro), Azure service depth + GCP breadth (later in C),
write/lifecycle actions beyond invoke/peek.
